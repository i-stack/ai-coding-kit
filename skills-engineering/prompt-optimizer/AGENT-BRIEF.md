# prompt-optimizer Agent 调用指南

## 一句话描述

用户主动请求优化提问时，先召回相似历史提问、复用 plan-grill 盘问澄清真实需求，再把模糊提问改写为结构化高质量提示词，透明展示供确认，确认前不回答原问题，确认后基于它回答；用户显式跳过确认时仍先展示优化稿并标注「未确认假设」，最后回写 `.plan-reviews/` 形成闭环。

## 何时调用

- **主动触发（POPT-001）**：用户输入「帮我优化提问」「优化这个 prompt」「改写我的问题」或 `@prompt-optimizer`。
- **跳过确认仍调用**：用户已请求优化、只要求不等确认时，按 POPT-005 例外分支处理；仅「直接回答，不要优化」属于不触发。
- **不触发**：普通对话、事实查询、代码生成等未请求优化的输入；本 skill 不做「发送时自动拦截」。

## 关键行为

1. 阅读 `SKILL.md` + `references/prompt_optimizer.md` 全文。
2. 历史召回（POPT-002）：针对原始提问 `recall` 相似历史，包成「不可信历史线索」边界；历史澄清结论仅作待验证线索，据此跳过盘问须标注「未澄清假设（来源：历史线索）」。
3. 盘问判定（POPT-003）：复用 plan-grill PG-000 门控 + PG-001~PG-003（仅 interview，不产出 PLAN.md）；存在阻塞性歧义先逐一盘问澄清，无歧义直接改写。
4. 改写（POPT-004）：宿主 AI 把原始提问重写为结构化高质量提示词（目标 / 上下文 / 具体要求 / 期望输出），并逐条核对改写验收判据。
5. 透明确认（POPT-005）：先展示优化后提示词，以「请确认或修正以上优化稿；确认前不回答原问题。」收尾；确认前不回答原问题。用户显式跳过确认时仍先展示优化稿、标注「未确认假设」后基于优化稿作答；改写改变对象或事实前提时不得跳过。确认后基于确认版回答。
6. 回写闭环（POPT-006）：在 `.plan-reviews/<date-slug>/` 写入 `PROMPT-OPTIMIZATION.md`（仅一行标题）、`QUESTION.md`、`CLARIFICATION.md`（记录豁免确认或依据历史线索跳过盘问）、`OPTIMIZED.md`（确认版 / 修正版 / 豁免确认版）并 `sync`。

## 不调用的情况

- 用户未请求优化提问的普通输入。
- 事实查询、翻译、闲聊、纯代码生成等不涉及「改写提问」的任务。
- 用户明确「直接回答，不要优化」。
