# problem-analysis 使用文档

## 概述

`problem-analysis` 是问题前置分析 skill，确保 AI 在**回答之前**充分理解问题、检验逻辑、拆解真实需求。它是所有含判断任务的第一道门控。

## 核心规则

| 规则 ID | 规则名称 | 说明 |
|---------|---------|------|
| PA-001 | 逻辑检验 | 审查问题是否含逻辑错误、矛盾前提、循环假设或虚假二分；仅「实质」四条独立判据命中才必须揭示 |
| PA-002 | 第一性原理 | 推理/取舍类从底层需求拆解；用户未提出路径则跳过路径评估；事实类走查证，不从第一性原理推导 |
| PA-003 | 理解门控 | 静默 / 出块后作答 / 停确认 三态互斥；完成前不开始正式回复 |

## 问题分析块

显式作答或停确认时，输出独立的「问题分析」块。字段名固定：

```
问题分析
逻辑检验：<发现的逻辑缺陷，或「无」>
真实需求：<第一性原理拆解后的底层目标>
路径评估：<当前方案是否最优；若有更优解，一句话说明；停确认时写「未确认，不推进」>
```

问题清晰、无路径或事实类时静默通过，不输出该块。表层交付物与底层目标互相替代时停确认：块后只问确认问题，确认前不推进方案。分页仍能达成流畅度属于手段关系（更优路径，出块后作答），不是停确认。

## 与其他 Skill 的分工

| Skill | 动作时机 | 关注点 |
|-------|---------|--------|
| problem-analysis | 回答**之前** | 问题的合理性与真实需求 |
| engineering-discipline (GR-002) | 描述不清时 | 前置确认补全缺失信息 |
| cognitive-reasoning (GR-013) | 判定题型时 | 事实查证 vs 推理拆解 |
| cognitive-reasoning (GR-010) | 回答**之中** | 自身论证质量 |
| cognitive-reasoning (CAM) | 用户强确信时 | 挑战用户结论 |
| plan-grill | 本 skill 完成后 | 实现方案决策树 |
| cognitive-reasoning (GR-011~013) | 回答**之中/之后** | 结论的外部验证 |
| engineering-discipline | 全流程 | 输出结构纪律 |

## 加载方式

含判断的技术问题、方案讨论、实现请求、架构取舍时默认加载，不依赖用户说出「第一性原理 / 深层需求 / 问题偏差」。纯机械执行时跳过。
