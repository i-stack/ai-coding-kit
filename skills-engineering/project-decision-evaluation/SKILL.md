# Project Decision Evaluation

## 必读规则

命中本 Skill 时，必须先完整阅读 [项目决策与持续评估框架](references/project_decision_framework.md)，并按其门禁、证据、评分、状态和复盘规则执行。不得以本入口摘要替代参考文档全文。

## 何时加载

**使用本 Skill：**

- 用户要求判断一个商业项目、产品方向或内部创新是否值得做。
- 用户要求进行立项、Go/No-Go、MVP 实验、项目排序或终止判断。
- 用户要求对已运行项目重新评分、设定停止条件或安排复盘。

## 何时跳过

- 只审查代码、PR、技术架构健康度或具体实现方案。
- 只估算开发工期、拆分需求或锁定软件实施计划。
- 用户只要求解释 ROI、胜率、机会成本等单一概念。

同一请求同时涉及“项目是否值得做”和“软件具体怎么做”时，本 Skill 只负责前者；需求与实施计划由 `plan-grill` 或相应工程 Skill 处理。未通过项目决策前，不因本 Skill 自动扩展到代码实现。

## 执行流程

1. **识别决策对象**：确认项目类型、目标、时限、硬约束、机会成本和证据时点。
2. **执行硬门禁**：先检查决策者状态、合法合规、下行风险、资金和执行可行性。上位门禁不通过时，不得用高分覆盖。
3. **分离事实与假设**：对每项关键输入记录来源、日期、样本量、证据等级、置信度和可证伪条件。
4. **处理未知项**：不得虚构市场规模、付费意愿、成本、概率、合规意见或竞争数据。缺失数据能实质改变结论时，标记“待验证”并提出最小取证动作；不能用虚假精确分数填补缺口。
5. **设计最小实证**：需求尚未验证时，在完成实验安全检查后，为最致命假设定义成功、失败和无结论标准。
6. **评分与排序**：先写明项目类型、权重和阈值，再使用九维记分卡。ROI 和风险调整价值只是维度证据，不与加权总分并行裁决。
7. **输出唯一状态**：从永久否决、待专业审查、暂缓、先实验、有条件立项、立即立项、转型或终止中选择一项。
8. **闭合后续动作**：写明责任人、截止日期、激活条件、黄灯/红灯、退出计划和下一复盘点。

## 输出契约

默认在对话中输出评估；只有用户明确要求写入文件时，才创建用户指定的文档。输出至少包含：

```text
项目类型与目标
决策状态：<唯一状态>

硬门禁
- <通过 / 不通过 / 待专业审查 + 证据>

九维评估
- <分数、权重、证据、置信度>
- 数据不足时：<不输出虚假精确总分，列出缺口>

关键假设与最小实证
- <假设、成功/失败标准、成本上限>

决策理由
- <事实 → 推断 → 结论强度 → 可证伪条件>

后续动作
- <责任人、截止日期、触发条件、下一复盘点>
```

完整评分时必须展示权重合计为 100%、计算口径和项目类型特殊规则。信息不足时，允许输出“暂缓”或“先实验”，不得为完成记分卡而猜测。

## 安全与权限

- 本 Skill 只产生评估和建议，不自动立项、投资、采购、发布、终止项目或联系外部人员。
- 法律、监管、医疗、重大资金或不可逆结论必须依据可问责的专业意见和一手证据；缺少时输出“待专业审查”或“暂缓”。
- 用户的请求是评估，不等于授权执行评估中的外部操作。
