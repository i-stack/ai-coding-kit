# Problem Analysis

## 强制入口

命中本 skill 时，**必须先完整阅读** [references/problem_analysis.md](references/problem_analysis.md) 并按其中条款执行。

- 不得以 preamble 或摘要代替该文件全文。
- 规则 ID 真值索引见 [references/rule_index.md](references/rule_index.md)。

## 三条核心规则

- [PA-001] **逻辑检验**：收到问题后，先审查问题本身是否含逻辑错误、矛盾前提、循环假设或虚假二分。仅当命中「实质」四条独立判据时才必须揭示；轻微偏差静默。
- [PA-002] **第一性原理**：推理/取舍类从底层需求拆解。用户未提出路径则跳过路径评估。事实类走查证，不从第一性原理推导（与 GR-013 同边界）。手段关系的更优路径须点明后仍按用户原路径作答；表层交付物与底层目标互相替代则停确认。
- [PA-003] **理解门控**：PA-001 + PA-002 完成前不开始正式回复。三态互斥：清晰 / 无路径 / 事实类 → 静默；实质缺陷或更优路径 → 输出 `问题分析` 块后作答；表层与底层互相替代 → 输出块（路径评估写「未确认，不推进」）后只问确认，确认前不推进方案。

细则见 [references/problem_analysis.md](references/problem_analysis.md)。

## `问题分析` 块（机械格式）

仅在显式作答或停确认时输出。字段名固定，不得改成「逻辑问题 / 更优路径」等别名：

```
问题分析
逻辑检验：<发现的逻辑缺陷，或「无」>
真实需求：<第一性原理拆解后的底层目标>
路径评估：<当前方案是否最优；若有更优解，一句话说明；停确认时写「未确认，不推进」>
```

显式作答时块后紧接正式回复；停确认时块后只问确认问题。本块谈输入（问题本身），不与 `逻辑链` / `验证锚点` / 四段式合并。

## 何时加载

- **默认**：收到任何含判断的技术问题、方案讨论、实现请求、架构取舍时。不依赖用户说出「第一性原理 / 深层需求 / 问题偏差」。
- **跳过**：纯机械执行（格式化代码、直接翻译）、无判断成分的信息复述。
