# 五步推进（Learning Loop）详规

> **真值来源**：本文件为唯一详规正文。`learning-loop/SKILL.md` 为入口。各端副本（`SKILL.md` / `AGENT-BRIEF.md` / `OUT-OF-SCOPE.md` / `references/`）由 `scripts/sync-skills.sh` 同步。

## 定位与边界

- 本 skill 把「目标先定 → 主干先立 → 习惯用类比先跑起来 → 新问题才拆到事实往上推 → 做出来挨打」用作任务推进顺序。
- 五步是启发式流程，适用于个人学习与一般问题求解；生产流程优化不属本 skill 范围。
- 本 skill 在用户原请求的授权范围内产出分析、实现与验证。跨模型审查需要单独显式授权；问题检验、真值接地与需求盘问分别由 `problem-analysis`、`cognitive-reasoning`、`plan-grill` 承担，`depends_on` 已在 frontmatter 声明三者。

## LL-001 触发门控

- **触发**：用户输入「按五步来」「用学习闭环」或 `@learning-loop`，并给出待解决的具体任务。
- **不触发**：普通对话、事实查询、翻译、闲聊、纯机械改动、代码生成等未显式请求五步推进的输入；未触发时不参与任务执行。
- 本仓库 skill 均为被动触发，无发送时自动拦截机制，本 skill 不假设该机制存在。
- 五步是内部推进顺序。用户显式要求查看过程时输出一份五步清单，输出复用既有主答与四段式结构，不新增机械 anchor 块。

## LL-002 目标先定

- 用一句话写明可演示、可失败的交付物；不写「学编程」「学物理」这类无交付物的目标。
- 明确定义何为失败：如两周后讲不清主干约束，或做不出最小可用原型。
- 列当前已知的最简工具清单作起始工具箱，不作封闭大纲；清单外材料按与目标的相关性判断，探索性学习与补充基础不排除。
- 完成标准：能向外人说清在解决什么具体问题；当前材料对应目标的哪一项可指认。
- 翻车信号：先买课、先刷基础语法、收藏大量教程，却说不清短期交付物。
- 真实需求与表层交付物互相替代时，交由 `problem-analysis` 的停确认态处理。

## LL-003 主干先立

- 先提炼少量核心主干问题，用自己的话简短说明每一点；检验标准是抽掉该点整套逻辑是否坍塌。
- 主干未建立前，孤立记忆 API、手册明细与边角个案不占主要精力；任务确实依赖的细节除外。
- 遇到细节先问它挂在哪根主枝；挂不上则暂缓，不开新叶子。
- 完成标准：一页树状结构（树干 + 少量主枝）可复述。
- 翻车信号：笔记详尽，但答不上该领域在解决什么核心约束。

## LL-004 类比优先

- 任务先分类：业内有通例或已有成熟解法 → 走复用；尚无有效解法或现有解法成本过高 → 转 LL-005。
- 复用路径：找最小可运行参考对象，先做足以验证流程的基线版本；清楚界定哪些直接沿用成熟惯例、哪些是场景微调。
- 类比只用于让系统运转，不作为「事情只能这样做」的证明；复用结论不覆盖 `problem-analysis` PA-002 对先例正当性的审查。
- 完成标准：最小版本可跑通，复用与微调边界可指认。
- 翻车信号：日常任务从原子重新推导，或把行业惯例当成自然律。

## LL-005 三类约束深拆

- 启动条件：常规惯例阻碍目标达成、成本过高，或做全新事物。
- 写下正在阻碍进展的惯例表述，把约束分为三类，并允许获得新证据后重新分类：
  - 客观事实：守恒定律、原材料基准价、时间、能量、尺寸等不可违反的约束。
  - 人定规则：法律法规、行业标准、审核流程、组织架构；在其仍有效时纳入可行域，并追问适用范围、修改成本与责任主体。
  - 历史习惯：竞品惯例、历史报价、传统做法；取消默认正当性，删除前查明它是否承载安全、兼容、可靠性或组织约束，并为必要功能准备替代机制。
- 从不可违反的事实与当前有效边界共同出发推导最小可行结构；第一性原理不等于只保留物理约束。
- 完成标准：形成「既有惯例 / 客观事实与有效边界 / 自下而上推论」三列分析，推论指出具体切入点并说明未采纳惯例后的功能覆盖或风险。
- 翻车信号：把主观愿望当第一性原理；把人为协议、契约误当物理事实强行颠覆。

## LL-006 闭环校准

- 实验前定义观察指标：假设成立会看到什么现象；假设错误会出现什么偏差。
- 输出可失败的验证清单（可测、可暴露问题），并写明向具备专业能力的人、尤其直言不讳者寻求严苛反馈的对象与方式。
- 遭遇失败或异常时只标记模型中被证伪的具体节点，不推翻整个主干。
- 完成标准：输出包含真实客观反馈的获取路径（测试数据、运行结果、专业评审）与被修正认知点的记录位。
- 翻车信号：停在理论推导；把失败归咎于外部环境且核心模型一字不改。
- 用户明确要求实施时，验证清单中安全、必要且本地可执行的项目应在当前任务内执行；纯分析请求只输出清单，见 LL-007。

## LL-007 授权与执行边界

- 执行范围服从用户原请求：纯分析、方案或解释请求不修改文件和外部状态；明确要求实现、修复或构建时，可调用完成交付所必需的工具，并按风险执行相称的本地验证。
- 实现授权不自动包含部署、发布、删除数据、发送消息或其它高影响外部动作；这些动作按宿主安全与授权规则处理。
- 不主动发起 `cross-model-review` / `auto-code-review`；这两类专门审查工作流要求用户单独显式授权。
- 不新增机械输出块，避免与 `.agents/composition.md` 的 L0–L5 块发射顺序和多技能叠加预算冲突。
- 需要计划锁定时交由 `plan-grill`；需要专门审查工作流时先取得对应授权。普通本地测试与构建在实现请求中不需要额外授权。
- 纯分析请求的输出限于五步分析、三列约束表、观察指标、可失败验证清单与求反馈对象；实现请求还应包含实际交付物和验证结果。

## LL-008 证据口径

- 五步流程是作者综合与操作展开，不是当事人提出的完整方法，也不是经对照实验验证的通用学习定律。
- 来源按证据强度分 A / B / C 三级；带 C 级标注的转写只作待核实线索，不作确定原话引用。
- 方法归属、证据等级与核验链接以 [provenance.md](provenance.md) 为运行时来源表；未列入该表的归属不得凭记忆补全。
- 「物理是规律，其余都是建议」的可用含义是「不把惯例误当自然定律」，不构成对法律、安全与伦理约束的豁免。
- The Algorithm（质疑需求 / 能删就删 / 简化优化 / 加速周期 / 最后自动化）属传记记录的生产优化启发式，与个人学习流程分轨，不在本 skill 内套用。
